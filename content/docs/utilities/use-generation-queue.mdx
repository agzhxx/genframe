---
title: useGenerationQueue
description: Runs the generation queue's jobs on your driver, a few at a time. It knows nothing about any API, and everything stops when it unmounts.
---

The queue's [reducer](./generation-queue-reducer.mdx), run on a driver: jobs wait in line, the
next ones start while there's room, and each run reports its progress and then its result or its
failure. [GenerationQueue](../components/generation-queue.mdx) shows the jobs; its page has the
hook running live, on the [simulated generator](./simulated-generator.mdx).

## Installation

```npm
npx shadcn@latest add @genframe/use-generation-queue
```

Or by URL:

```npm
npx shadcn@latest add https://agzhxx.github.io/genframe/r/use-generation-queue.json
```

The URL form needs the namespace mapped too ([Add the registry](../index.mdx#add-the-registry)):
the hook brings the [queue's reducer](./generation-queue-reducer.mdx), and shadcn finds it through
`@genframe`. It lands in `hooks/use-generation-queue.ts` and needs no npm packages.

## Usage

```tsx
import { useGenerationQueue } from "@/hooks/use-generation-queue"

const queue = useGenerationQueue({ driver, concurrency: 2 })

const id = queue.submit({ kind: "video", prompt: "A ferry crossing a bay", ratio: "16:9" })
queue.cancel(id)
queue.retry(id)
queue.remove(id)
```

`queue.jobs` is every job, newest first. A submitted job starts at once when there's room, in the
same tick, so it never shows as queued for a moment; otherwise it waits in line, in the order of
submission. Jobs are numbered by kind (image 1, image 2, video 1) and never renumbered.

### Writing a driver

A driver is your generator behind one function. `run` gets the job and resolves with what it
made, or rejects to fail it; the error's message is what the card shows. It reports progress as it
goes, and stops when its signal aborts: the job was canceled or removed, or the queue unmounted.

```ts
import type { GenerationDriver } from "@/hooks/use-generation-queue"
import type { GenerationRequest } from "@/lib/generation-queue-reducer"

interface ImageRequest extends GenerationRequest {
  model: string
}

// What your API says about a generation it's working on.
interface Status {
  state: "working" | "done" | "failed"
  progress?: number
  message?: string
  image?: { url: string; width: number; height: number }
}

export const driver: GenerationDriver<ImageRequest> = {
  async run(job, { signal, progress }) {
    // Your API: here, one that takes a request and is polled until it's done.
    const response = await fetch("/api/generations", {
      method: "POST",
      body: JSON.stringify({ prompt: job.prompt, ratio: job.ratio, model: job.model }),
      signal,
    })
    const { id } = (await response.json()) as { id: string }
    for (;;) {
      await new Promise((resolve) => setTimeout(resolve, 1000))
      signal.throwIfAborted()
      const status = (await (await fetch(`/api/generations/${id}`, { signal })).json()) as Status
      if (status.state === "failed") throw new Error(status.message)
      if (status.image) return { src: status.image.url, width: status.image.width, height: status.image.height }
      progress(status.progress ?? null) // from 0 to 1, or null when it can't tell
    }
  },
  // How long a run should take, for the time left before there's progress.
  estimate: (request) => (request.model === "fast" ? 4000 : 12_000),
}
```

Whatever a stopped run reports later is ignored, so a driver that can't cancel its work is safe:
the [reducer](./generation-queue-reducer.mdx#late-events) ignores late events, and the hook stops
listening to a run once its signal aborts. Each attempt is a run of its own: a retry calls `run`
again, with the same job at its next attempt.

### Refunds

A job canceled before it started is marked refunded: it never reached the driver. Once it runs,
its cost is spent, and the card says it was canceled.
